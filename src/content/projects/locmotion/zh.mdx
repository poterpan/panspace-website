## 背景與問題

測試依賴定位的 iOS App 時，Xcode 和一般工具多半只能把定位設成一個固定點，或沿路線等速瞬移。真實的移動不是這樣：車子會加速、在路口停下，GPS 訊號也會飄。用不真實的軌跡測試，很多跟移動有關的邏輯根本測不到。

## 我的角色

獨立開發：模擬引擎、裝置連線、後端 API 與網頁控制台。

## 做法與技術決策

後端是 FastAPI，分成四個模組：裝置連線、路線規劃、移動引擎與 GPS 雜訊。網頁控制台用 Leaflet 畫地圖，透過 WebSocket 即時顯示裝置位置。

**路線**用 OSRM 規劃開車、步行或騎車路線，支援多個中途點；紅綠燈位置從 OpenStreetMap 的 Overpass API 取得，地址搜尋走 Nominatim。這些公開服務偶爾會慢或失敗，所以都加了重試與備援鏡像。

**移動引擎**以 2 Hz 連續注入座標，套用加減速曲線、速度變異，在紅綠燈自動停頓；靜止時也會加入微小漂移，不會像固定點那樣完全不動。

**裝置連線**用 pymobiledevice3 走 DVT 的定位模擬服務，USB 與 Wi-Fi 都能用，iOS 17 前後的連線方式也都支援。連線流程參考了開源專案 GeoPort，所以整個專案依 GPL-3.0 授權釋出。

## 成果

可以在地圖上點出路線、按下開始，裝置就沿路線移動；支援暫停、中途改道、循環繞行、返回起點，也能匯入 GPX 或 GeoJSON 軌跡。原始碼開源在 GitHub。

## 學到什麼

模擬得像不像，取決於細節：加速、停等和雜訊少了任何一個，軌跡就不像真實的移動，App 裡跟移動有關的邏輯也就測不到。

也學到要誠實寫出限制。定位模擬協定不支援速度欄位，直接讀速度的 App 會顯示 0，從位置差分計算速度的導航 App 則正常，這些我都寫在 README 裡。
