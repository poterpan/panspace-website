## 背景與問題

社團合買 OpenAI、Anthropic 的訂閱，再把費用分攤給成員。每個月用試算表追誰繳了、誰還沒繳、截圖對不對得上，很快就變成一件沒人想做的事。

## 我的角色

獨立設計與開發：資料模型、Discord 機器人、後端 API、兩個前端、測試與部署。

## 做法與技術決策

把整個繳費流程搬進成員本來就在用的 Discord。成員按「繳費」按鈕、選付款方式就完成，一次送出會結清他這一期所有的訂閱；還沒綁定身分的人，在同一個流程裡選自己的名字就好。

後端是一個 Cloudflare Worker，帳本存在 D1，付款截圖放在私有的 R2。每天的排程負責開帳、催繳和截圖保存期限，所有通知都經過紀錄表去重，重跑也不會重複發送。

幾個刻意的設計：

- **每期金額凍結**：方案改價不會改到過去的帳單。
- **核心與通道分離**：帳務邏輯不依賴 Discord，LINE 和 Telegram 的介面已經預留。
- **後台整個放在 Cloudflare Access 後面**，前端與 API 同源，Worker 端再驗一次 JWT 和信箱白名單。
- **CSV 匯入先預覽差異**：新增、暫停、恢復哪些訂閱，確認後才寫入，可以重複執行。
