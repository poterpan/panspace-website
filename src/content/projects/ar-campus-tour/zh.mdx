## 背景與問題

新生和訪客常在校園裡找不到路，而一般導覽 App 依賴 GPS，在大樓密集的校園裡誤差動輒 5 到 15 公尺，分不出使用者到底站在哪一棟樓前，也就做不到「走到哪、講到哪」。

## 我的角色

四人團隊中，我負責整體規劃與系統架構、AR 定位導覽（Geospatial 定位、錨點與接近觸發），以及跨平台的工程整合與 CI/CD。導遊角色與 UI、LLM 對話與語音、AR 校園貓的強化學習分別由其他三位組員負責。

## 做法與技術決策

**定位**用 ARCore Geospatial API：手機相機畫面和 Google 街景建立的特徵點雲比對，把定位從 GPS 的公尺級誤差修正到一公尺以內。提案階段我先在校園實測，確認 VPS 涵蓋足夠，才決定以它為核心。

定位完成後，五個景點會在實際經緯度上建立錨點；App 每秒計算使用者和最近景點的距離，進入 30 公尺內導遊就會現身。錨點以景點 id 快取，解析中的請求也會去重，避免同一個景點建立兩次。

**架構**上把程式碼依 Assembly Definition 切成景點資料、AR 定位、導遊、校園貓與 UI 五個模組，降低組員之間的編譯耦合和 Unity 場景合併衝突。會動到主場景的工作集中在我這裡，其他組員交付獨立模組，讓四個人能平行開發。

**CI/CD** 用 GitHub Actions 自動建置 iOS（發佈到 TestFlight 公開測試）與 Android 版本，金鑰由 secret 在建置時產生，不進版控。
